# 与常见 Markdown 转换工具的差异

> 定性对比，基于公开资料和本项目实测；工具版本变化很快，建议以各项目最新文档为准。
> 这里不评价“谁更好”，只说明**侧重点不同**。

## 一句话总结

- **通用文档转 Markdown**：MarkItDown、Pandoc、Docling 更合适。
- **只要 PDF 文字层、表格不复杂**：PyMuPDF4LLM / pdfplumber 更快。
- **要 PDF 版面/OCR/表格模型**：MinerU 原版、Marker、Docling 都可以。
- **要中文环评复杂表 + 合并单元格 + 扫描件 + 页码锚点 + QA + GUI/一键装依赖**：本项目。

## 逐个说明

### MarkItDown（Microsoft）

- 优点：格式覆盖广（Office、PDF、HTML、图片等），API 简单，适合“先把文件变成 Markdown 给 LLM 看”。
- 局限：通用转换，不针对中文环评表的跨行跨列/整页外框/跨页续表；没有页级质量指标、页码锚点、GUI 或自动装 MinerU。
- 什么时候选它：文件类型杂、只要可读文本、不要求表格结构严格。

### MinerU（上海 AI Lab）

- 优点：中文版面、表格、公式、扫描件 OCR 都强；CPU 可用 ONNX 小模型。
- 局限：输出是 `middle_json`，表格模型在多行单元格上可能按视觉行把文字打散（例如 `石油烃（C10-C40）` 变成 `（石C10油-C烃40）`）；没有页级 QA、GUI、自动装依赖。
- 本项目与它的关系：**MinerU 是本项目的 PDF 主引擎**；本项目在其上做线条网格重建、standard 补漏、原生页兜底、页码锚点、QA 和桌面/安装器。

### Docling（IBM / LF AI）

- 优点：通用文档理解、布局和表格模型不错，生态活跃。
- 局限：通用场景优先，不针对环评表的复选框/上下标/跨页续表；没有本项目的页覆盖率 QA、GUI 和一键安装。
- 什么时候选它：通用文档 RAG、需要统一的多格式解析。

### Pandoc

- 优点：Office/Markdown/HTML 互转非常成熟、稳定、极轻。
- 局限：不处理 PDF 版面、扫描件、复杂表；没有 OCR。
- 什么时候选它：DOCX/HTML/LaTeX 互转，不需要 PDF 解析。

### PyMuPDF4LLM / pdfplumber

- 优点：快、轻、纯文字层提取；pdfplumber 的线条/表格 API 很好用。
- 局限：表格结构靠规则推断；遇到复杂环评表会串列、粘表；扫描件无文字层就无能为力。
- 本项目与它的关系：本项目也用 PyMuPDF/pdfplumber，但只把它们用于**单元格取字、线条读取和原生兜底**，主结构由 MinerU + 线条网格重建负责。

### Marker

- 优点：PDF → Markdown 效果好，支持表格/公式/图片。
- 局限：通常依赖 GPU，部署成本较高；不是中文环评场景专用，没有本项目的一键安装/QA/GUI。
- 什么时候选它：有 GPU、追求通用 PDF→Markdown 质量。

### 在线转换（Smallpdf、iLovePDF 等）

- 优点：不用装环境，上手快。
- 局限：要上传文件，涉密/客户数据不合规；通常没有 API、页级 QA、离线能力和复杂表结构保证；有页数/次数限制。
- 本项目：默认本地处理，装好后离线；API 只建议内网使用。

## 什么时候选本项目

- 你要把**中文环评报告书/报告表**喂给大模型，表格不能串列；
- 报告里有**跨行跨列、整页外框、跨页续表、上下标、复选框**；
- 有**扫描件**或文字层损坏的 PDF；
- 需要**页码锚点**、按章节切片、页级质量指标；
- 需要**图形界面**给非技术同事用；
- 需要**首次运行自动装依赖**，不想手动配 MinerU/CUDA/模型；
- 需要**离线/内网**处理，不能上传客户文件。

## 什么时候选别的

- 只要把 DOCX/HTML 转 Markdown：Pandoc 更轻。
- 文件类型很杂、只要可读文本：MarkItDown。
- 只要 PDF 文字层、表格简单：PyMuPDF4LLM/pdfplumber。
- 有 GPU、追求通用 PDF→Markdown：Marker/MinerU/Docling 都可以。
- 不想装任何环境、文件不涉密：在线转换最省事。
